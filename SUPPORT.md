# Support

Slate is open source and self-hosted. There is **no support contract, SLA, uptime commitment, or
official hosted service** provided with this repository.

## Where to get help

| Need | Where |
| --- | --- |
| Setup, configuration, running locally | [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) |
| Deploying to your own host | [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) |
| How the code fits together | [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) |
| A reproducible bug | Open an issue with the template filled in |
| A question or idea | Open a discussion, if the repository has discussions enabled |
| A security problem | [SECURITY.md](SECURITY.md) — never a public issue |
| Commercial or hosting help | Not offered by this project |

## What to include in an issue

- What you expected and what happened.
- Exact steps to reproduce.
- The commit you are on, your OS, Node version, and whether you used Firebase emulators.
- Relevant logs with **tokens, keys, uids, emails and board contents removed**.
- For UI problems: a screenshot or recording, and the browser/device.

## What maintainers will not do

- Debug your deployment, Firebase project, provider account, domain, or TLS configuration.
- Provide legal, privacy or compliance advice. The shipped legal documents are DRAFT templates.
- Recover data from your Firebase project.
- Support modified versions or forks; reproduce the problem on `main` first.

## Operator responsibilities

If you run Slate for other people you are the operator, and you are responsible for:

- your own Firebase project, AI provider accounts and their costs;
- your privacy policy and terms, and any consent or age requirements where your users live;
- your legal obligations for the data you process (including board images sent to an AI provider);
- backups, monitoring, incident response, and complying with AGPL section 13 if you run modified
  code as a network service.

## Response expectations

This is a volunteer-maintained project. Issues are triaged when maintainers have time. A clear,
minimal reproduction is the single biggest factor in getting a fix. Issues that are out of scope,
support requests for your own deployment, or reports without reproductions may be closed.
